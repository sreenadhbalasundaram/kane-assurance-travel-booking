# Kane CLI Assurance — StayNest Travel Booking Demo

A ready-to-fork assurance project that maps Kane CLI Assurance to the Software Testing Lifecycle for the StayNest travel booking journey.

**Application under test:** https://my-testing-repo-main.vercel.app/travel-clone-app
**Local mock:** `http://localhost:3000/travel-clone-app`

## STLC mapping

| Phase | Workflow | Kane CLI surface |
|---|---|---|
| Requirements Analysis | `1-requirements-analysis.yml` | `context ingest` + `context extract` |
| Test Planning | `2-test-planning.yml` | `context review` + `cover gaps` |
| Test Design | `3-test-design.yml` | `design tests` |
| Test Development | `4-test-development.yml` | `testmd run` |
| Test Execution | `5-test-execution.yml` | `testrun run` |
| Coverage & Reporting | `6-coverage-reporting.yml` | `cover` + `cover gaps` |
| Maintenance | `7-maintenance.yml` | `maintain reconcile` + `maintain evolve` |
| Full pipeline | `run-all-stlc-demo.yml` | All phases |

## Product flow

`/travel-clone-app` lists grouped homes → `/rooms/{id}` shows details → `/book/{id}` calculates the special-offer total → `/pay/{id}` accepts UPI, Cards, Netbanking, or UPI QR → confirmation displays the booking reference.

The local Next.js mock implements the same route and API contracts so the assurance suite can run without depending on a third-party deployment. The deployed URL remains the default target for demos.

## Quick start

```bash
cd app
npm install
npm run dev
# Open http://localhost:3000/travel-clone-app
```

For Kane CLI:

```bash
npm install -g @testmuai/kane-cli
kane-cli login --username "$LT_USERNAME" --access-key "$LT_ACCESS_KEY"
./scripts/run-demo.sh docs/prd-travel-booking.md prd-travel-booking https://my-testing-repo-main.vercel.app/travel-clone-app
```

## GitHub Actions

Add `LT_USERNAME` and `LT_ACCESS_KEY` under repository Actions secrets. Optional Vercel secrets are only needed if you want workflow 0 to deploy the local mock. Run workflow 1 first, approve the derived use-cases in workflow 2, then design and author tests before batch execution.

The maintenance demo uses `docs/prd-travel-booking-v2.md` after the v1 graph and suite have been created.

## Repository structure

```text
.github/workflows/   STLC phase workflows
app/                 Local StayNest Next.js mock
docs/                v1 and v2 travel-booking PRDs
scripts/             Local full-demo runner
```

The `.context/` and `.testmuai/` directories are generated by Kane CLI and intentionally ignored by git.
